# C++ から Rust への移植

## 等価性が先、最適化は後

- 移植の初期は、アルゴリズム・演算順・スレッド構成を C++ に合わせる。並列化などの最適化は、等価性が取れた後に別コミットで行う
- 挙動を変える修正(バグ修正)と、言語を移す変更を同じコミットに混ぜない。バグ修正は B(C++)で先に行い、Rust はそれを移す

## 数値の罠

- Eigen は列優先(column-major)。行列を配列として受け渡すときは並びを確認する
- 浮動小数点の演算順が変わると結果が変わる。和の順序、`fma` の有無、`-ffast-math` の有無を揃えて記録する
- 回転の表現(クォータニオンの成分順、`so3` の指数写像と対数写像の符号・微小角の扱い)を C++ 側の実装と突き合わせる
- IKFoM(MTK)は多様体をテンプレートで合成している。Rust 側は手書きの状態型になるため、状態の並び順・次元・共分散のブロック位置を C++ と一致させてから進める

## unsafe

- `unsafe` は最後の手段にする。使うときは、直前のコメントに、守られている前提条件を書く
- 移植の目的の一つが安全性の比較である。`unsafe` の行数と箇所を、プランの検証結果に記録する
- FFI や生ポインタを使う箇所は、メモリ安全レビュー担当の確認を受ける

## ビルド設定の確認

C++ 側の `CMakeLists.txt` はビルドタイプを `Debug` に設定しつつ、`CMAKE_CXX_FLAGS` に `-O3` を指定している。実際に有効な最適化フラグは、ビルドログで確認してから性能比較に使う(要確認)。
