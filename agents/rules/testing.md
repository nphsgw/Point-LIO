# ゴールデン出力と許容誤差

## 期待値の出典

期待値の出典は、プランの「新規テストケース」と、フェーズ1で検証済みの B(バグ修正後の C++)の出力とする。実装中の Rust コードの出力を正解にしない。

- 期待値を通すために Rust 側のテストを書き換えない。期待値が誤りと疑われたら、停止してバグ台帳に起票する
- 期待値(ゴールデン出力・評価データ)の更新は、人の承認を得てから、専用のコミットで行う。理由と元の実行条件を添える
- 評価データには SHA256 とバージョンを記録し、ハッシュが一致しない状態でテストを走らせない

## 許容誤差

- 許容誤差は結果を見る前に決め、A を10回実行したときのばらつきを基準にする
- 許容誤差を、テストを通すために広げない。変える必要があれば停止して報告する
- 軌跡全体のビット一致は求めない。判定はステップ単位の差と、統計指標(ATE/RPE、Chamfer 距離)で行う

## 骨抜き禁止

- 何も守っていないアサーション(値が存在するだけを確認する、など)を書かない
- 環境がないと黙って成功扱いになる条件付きスキップを入れない。評価データがなければ失敗にする
- ループ内の `assert` は、対象が空なら何も検証しない。件数も確かめる
- 修正を戻すとテストが落ちることを確かめる。修正の前後どちらでも通るテストは、ないより悪い
- バグ修正の回帰テストは、A では失敗し B では通ることを確認してからコミットする
- 新しいケースは既存テストの横に足す。既存テストの入力や期待値を書き換えない。削除・スキップには理由を書く

## 時刻と非決定性

- 壁時計に依存しない。ただし、**センサのタイムスタンプは検証対象**であり、固定せず入力どおりに扱う
- スレッド数(`MP_PROC_NUM`)と並列処理は結果に影響する。比較する実行ではスレッド数を固定して記録する
- 乱数やハッシュ順に依存する処理は、シードか順序を固定する

## 性質ベースのテスト

次は、期待値の一致ではなく性質で検査する。

- 回転行列の直交性と行列式、クォータニオンの正規化
- 共分散行列の対称性と半正定値性
- タイムスタンプの単調性
