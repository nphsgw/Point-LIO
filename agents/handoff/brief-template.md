# 実装の指示書:【プラン名の手順 N、または台帳 ID】

あなた(Codex)は、このリポジトリの AGENTS.md と、下に挙げるルールに従って、1つの作業だけを実装する。実装のあとは別のセッションがレビューする。

## 1. 対象

移植とバグ修正のどちらか一方を残す。

- 移植: プラン【agents/plans/….md】の手順6の【N】「【項目の文】」
- バグ修正: [台帳](../../docs/bug-ledger.md)の【BL-NNN】。決定の欄の「B で直す」の内容だけを実装する
- 読むもの: 【プランの節、または台帳の行】、【agents/rules/….md】、【C++ の対象ファイル】

## 2. 変更してよいファイル

テストのファイルと実装のファイルを分けて書く。一覧の外を変える必要が出たら、変えずに止まり、報告に書く。

| 種類 | ファイル |
| --- | --- |
| テスト | 【記入】 |
| 実装 | 【記入】 |

## 3. 進め方

1. 【移植: プランの「新規テストケース」の行/バグ修正: 台帳の決定に書かれた回帰テスト】をテストに書く
2. テストを実行し、落ちることを確かめる。Red のコマンド: 【記入】。期待する落ち方: 【記入】。落ちたアサーション(値・位置)を報告の `red.failure` に書く
3. 実装し、4節の検証を通す。2節の「実装」のファイルだけを修正前に戻せば Red に戻る形にする(テストのファイルに修正を入れない。レビューでは実装のファイルだけを退避して Red を取り直す)

## 4. 検証

【作業に合う行だけを残す】

| 検証 | コマンド | 期待 |
| --- | --- | --- |
| Rust のテスト | `rust/run.sh test --release --locked --offline` | 終了0 |
| clippy | `rust/run.sh clippy --release --locked --offline --all-targets -- -D warnings` | 終了0 |
| fmt | `rust/run.sh fmt --all -- --check` | 終了0 |
| Rust のゴールデン照合 | `rust/run_math_golden.sh /tmp/<新しいディレクトリ>` | 終了0 |
| C++ の L1 テスト | `tests/math/run_math_tests.sh` | 終了0 |
| C++ のゴールデン照合 | `tests/math/run_math_golden.sh check` | 終了0 |
| 文書の検査 | `python3 -B tests/docs/check_docs.py` | 指摘が増えない |

Docker が使えずに実行できなかったものは、理由とともに報告し、通過とは書かない。

## 5. 禁止事項

- コミット、ブランチの作成・切り替え
- リポジトリの外(`/tmp` を除く)への書き込み。Docker のコンテナに、リポジトリと `/tmp` の外を書き込み可でマウントしない
- 許容誤差の変更、ゴールデン出力の `write`、評価データ・`eval/config/canonical` の変更
- バグを「直す」か「仕様として固定」するかの判断。台帳の決定にない修正
- `docs/bug-ledger.md`、`agents/rules/`、`agents/README.md`、`docs/README.md`、プランの編集
- 【この作業だけの禁止事項があれば記入】

## 6. 止まる条件

次のときは、推測で進めずに止まり、報告の `questions` に書く。

- プランか台帳の記述が曖昧で、実装が2通り以上に分かれる
- 5節の禁止事項に触れないと進めない
- 2節の一覧の外を変える必要がある
- B(C++)の挙動がプランか台帳の記述と食い違う
- ゴールデン照合が落ちる(ゴールデン出力の更新は人の承認が要る)

作業中に別の不具合に気づいたら、直さずに `ledger_candidates` に書く。

## 7. 報告

最後のメッセージは、指定した JSON スキーマに従う。実行していないコマンドは `commands` に入れない。
