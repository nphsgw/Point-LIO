# BL-011: B の通常 Log の修正と検証

2026-10-31、人が次の2点を承認した。

1. BL-011 は B で直す。通常分岐を `θ=atan2(‖K‖/2,c)`、出力 `(θ/‖K‖)K` にする。BL-008 の π 近傍の分岐は維持する。
2. 下端 θ=1e-3 の近似分岐と既存テストは今回は変えず、未解決の制約として台帳に残す。ゴールデン出力の更新は、修正の結果を示してから別途承認を得る。

## 修正

`include/IKFoM/IKFoM_toolkit/mtk/types/SOn.hpp` の通常分岐だけを変更した。従来の `theta = trace 条件 ? 0 : acos(c)` は、小角分岐の判定を保持するために残す。通常分岐の出力にはこの theta を使わず、K のノルムから atan2 の角度を求め、同じノルムで割る。sin を再計算しない。

π 近傍の条件、S の計算、軸の選び方、正規化、向きの判定は変更していない。小角の条件、`0.5K` の返値、既存テストの入力・許容誤差も変更していない。

## 回帰テストと L1

`tests/math/math_tests.cpp` に `So3Log.InvertsRoundedRotationBL011` を追加した。[再現記録](math-log-l1-reproduction.md)にある v と R の固定ビット列を使い、元の上限 `1e-12` を要求する。既存のケースは書き換えていない。

同じ回帰テストの本体を、固定イメージ内で次のソースに対してコンパイル・実行した。

先に保存した Rust L1 の200入力を同じビット列で修正後 B に与えると、全件が `1e-12` 以下で、最大誤差は `4.440892098500626e-15`。旧 B と旧 Rust がともに落ちた record 70 の誤差もこの値だった。旧 Rust の Log はまだ修正しておらず、修正後 B と比較すると200件中86件で出力のビットが異なる。移植の再開時には新 B の式へ合わせる必要がある。

## 下端の既知の制約

`v=(1e-3,0,0)` の誤差は修正前後とも `1.666666583390042e-10`。同じ角度の1000方向も小角近似分岐に入り、全件が `1e-12` を超える。この制約は承認どおり未修正であり、今回の L1 全17件の通過を「対象範囲全域で一律1e-12を達成」とは扱わない。
