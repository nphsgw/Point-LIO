# A のベースライン(演算順の変種 V0〜V4)

実施日: 2026-10-26。計画書のフェーズ0の項目4。[事前登録](metrics-preregistration.md)の「演算順の変種と感度分析」の1〜5を、A についてファイル駆動(`pointlio_offline`)で行った。ここで求める τ・RPE・Chamfer は感度分析で、合否には使わない。判定 J6 の Δ_gt と余裕は B の変種から求めるので、下の正解に対する ATE は A の値である。

## 条件

- 機械: AMD Ryzen 7 7700X(`meta.txt` の `cpu`)。イメージ `point-lio-noetic:pinned`(`sha256:4ffccd04…`、全パッケージが `docker/packages.lock` と一致)。コンパイラは gcc 9.4.0。
- ソース: C++ のソース(`src/`・`include/`)は、全36回とも `A-v1` と同一(`eval/variant_summary.py` が、各実行の `git_head` の木と作業ツリーの差分で確かめた)。
- 作業ツリー: 実行中に、別の作業(ゴールデン出力の作成と、文書・スクリプトのコミット)をしていた。そのため `git_head` は `ab0d966`・`06f2c08`・`d8eed8a` にまたがり、36回中35回は `git_dirty` が 0 でない。差分は `CMakeLists.txt` への別のターゲット(`math_golden`)の追加と、未追跡のファイル(`golden/`、`tests/math/math_golden.cpp`、`tests/math/run_math_golden.sh`、`eval/variant_summary.py`)だけで、`pointlio_offline` のソースとビルドのフラグには触れていない。各変種の実行は、`git_head` が違ってもビット一致した。
- フラグ: V0 は既定(`-O3 -g`)。V1〜V4 は `EXTRA_CXX_FLAGS`(`CMAKE_CXX_FLAGS_DEBUG` を置き換えるので、V0 に合わせて `-g` を付けた)。
- 実行数: 各 bag で V0 を10回、V1〜V4 を2回ずつ。`OMP_NUM_THREADS` は未設定。
- 指標: evo 1.37.1(`tests/harness/venv.lock`)。ATE は SE(3) 整列・スケールなし。RPE は 10 m と 10 フレーム。事前登録の「1 s」は evo に秒単位の区間がないので出していない(代わりに 10 フレーム)。Chamfer は `eval/chamfer.py`(0.1 m のボクセル)。
- 集計: `eval/variant_summary.py <bag> ~/data/slamrun-runs/a-variants-ab0d966 [正解]`。記録はリポジトリ外の `~/data/slamrun-runs/a-variants-ab0d966`。

## 分かったこと

- 各変種の中では、実行がすべてビット一致した(V0 は10回、V1〜V4 は2回ずつ)。中央値実行は、どちらの bag でも run01(全回が同じため)。
- avia の V0–V1 の差(ATE 1.024e-01 m など)は、ROS 経路の代理実験([fp-order-sensitivity.md](fp-order-sensitivity.md))の値と一致した。
- avia では V1 と V2 がほぼ同じ(ATE 2.2e-08 m)。FMA の有無が支配的で、`-march=native` の AVX2 以降はほとんど効かない。V3・V4(積和の結合なし)どうしの差は 1.05e-02 m。
- ouster の τ(ATE 8.7e-03 m)は、avia(1.0e-01 m)の約1/12。
- ouster の正解に対する ATE は 0.06940〜0.07036 m(幅 0.00096 m)。V0・V1 だけを見ていた時点の幅(約 0.0005 m)の約2倍。
