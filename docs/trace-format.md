# 内部トレースの仕様(草案 v1)

状態: **草案 v1(2026-10-26)。v0 の別セッションのレビューの指摘を反映した。v1 のレビューは未実施。実装なし**。[計画書](rust-reimplementation-verification-plan.md) §5 の要件と、[事前登録](metrics-preregistration.md)の判定 J1〜J4 を満たすための、C++(B)と Rust(C)に共通の記録の形式。入力の [PLIN 形式](harness-input-format.md)と同じく、Rust を書く前に確定する。

この版は、記録する段階・項目・識別子・間引き・地図の与え方を決める。バイト単位の配置(第7節)は、実装の前に別の版で確定する。行番号は `A-v1` のもの。

## 1. 目的と範囲

- 目的: 「最初にどの処理段階で契約が破れたか」を特定する。J1〜J4 の判定に要るものだけを記録する。
- 範囲: [state-definition.md](state-definition.md) 第1節のモード。`kf_input` の経路と、範囲内で通らない分岐(`time_seq.size()==0` の側、`src/laserMapping.cpp` 702〜771 行。`time_compressing` は必ず1件以上を返す)は記録しない。
- 記録は値を読むだけで、計算を変えない。トレースの有効・無効で出力がビット一致すること(完了条件1)を、両 bag で確かめる。

## 2. 識別子

| 識別子 | 定義 |
| --- | --- |
| `rec` | PLIN の入力レコードの通し番号(0 から)。C++ では、受信のコールバックに渡すメッセージの `header.seq` に入れて持ち回す(計算には使われない。完了条件1で確かめる) |
| `frame` | `sync_packages` が返したフレームの通し番号(0 から) |
| `grp` | フレーム内の時刻の組の番号 k(`time_seq` の添字)。LiDAR 更新は組ごとに1回 |
| `call` | 段階の呼び出しの通し番号(全体で 0 から)。イベントループの記録の主キー |
| `s7` | S7 の呼び出しだけの通し番号(0 から)。間引きに使う |
| `pid` | iVox に挿入した点の通し番号(0 から)。初期地図(S3)の挿入から数える。C++ では `IVoxNode` に、点の配列と並ぶ `pid` の配列を持たせる(計算を変えないことを完了条件1で確かめる) |

## 3. 段階

### 3.1 段階の一覧と、実際の呼び出しの順序

1. S1b(最初のフレームだけ: 重力の代入 409 行、`G_m_s2` の上書き 436 行、IMU の待ち行列の取り出し 414〜424 行)
2. S3a(`p_imu->Process` の中の `IMU_init`。初期化が終わるまで)
3. S2b(ダウンサンプル・時刻でのソート・`time_compressing`、449〜463 行)
4. S3b(`Set_init` 478 行と `acc` の代入 483 行。初期化が終わったフレームだけ)

## 4. 記録する項目

型は C++ の型のまま記録する(`double` は f64、点の座標などの `float` は f32)。状態は 42 個の f64(DIM=30 の多様体。`rot` と `offset_R_L_I` は 3×3 の行列を9値ずつ。並び順は第7節で決める)。

### 4.1 J1(自走の契約。入力だけで決まる量)

| 段階 | 項目 |
| --- | --- |
| S1a | `rec`、種別、受理か破棄か、破棄の理由(時刻の逆転、前処理の結果が空) |
| S1b | `frame`、`lidar_beg_time`、`lidar_end_time`、初期化が終わったか |
| S4・S5・S6・S7 | `call`、段階、`frame`・`grp`、呼び出し時の時刻(`time_current`、`time_predict_last_const`、`time_update_last`)、dt、予測のフラグ、`imu_last`・`imu_next` の `rec` |
| S9 | 出力の時刻 |

### 4.2 J3(段階の離散的な契約)

| 段階 | 項目 |
| --- | --- |
| S2b | 出力の点の数、各点の時刻(`curvature`)、`time_seq` |
| S6 | `satu_check[0..5]` |
| S7 | `valid`(`maximum_iter = 1` なので1回分)、戻り値(更新の成否)、LiDAR 更新の分岐(有効点が30以上か未満か)、点ごとの採否(平面の判定、`p_norm` の判定)、各点の近傍点の `pid` の列(順序つき。`esti_plane` は先頭の5点で解くので順序が数値に効く)、`effct_feat_num` |
| S3c・S8 | 挿入した点(`pid`、座標)、退避したセル |

### 4.3 J4(1ステップの数値)

| 段階 | 入口 | 出口 |
| --- | --- | --- |
| S2a | 受信したメッセージ(`rec`) | 前処理後の点(f32) |
| S2b | S2a の出力 | ダウンサンプル後の点(f32。平均の足す順は BL-007 で定める) |
| S3a | IMU の列(`rec`) | `mean_acc`、`mean_gyr`、初期化の件数 |
| S3b | `mean_acc`、設定の重力 | `rot_init`、`acc` |
| S4 | 状態、`time_current`、`time_predict_last_const` | 状態(dt の計算を段階に含める。事前登録の「dt の1つずれ」の注入を J4 で検出するため) |
| S5 | 状態、共分散、`imu_next` の時刻、`time_update_last` | 共分散 |
| S6 | 状態、共分散、`angvel_avr`・`acc_avr` | 状態、共分散、残差 `z_IMU` |
| S7 | 状態、共分散、組の点(機体座標) | 状態、共分散、残差 `z` と Jacobian `h_x`、組の点の世界座標(f32) |
| S9 | 状態 | 出力の `pos` と `q.coeffs()`(x, y, z, w の4値) |

### 4.4 J2 と完全性のためのハッシュ

すべての S4〜S7 の入口と出口で、状態と共分散のバイト列の 64 ビットのハッシュを記録する(1件 8 バイト)。共分散を間引いた呼び出しでも、J2(配線)と完了条件2をこのハッシュで確かめる。ハッシュの関数は第7節で決める。

### 4.5 段階の入力を完全にするための隠れた状態

S0 と S4〜S7 の入口に記録する: `imu_last`・`imu_next` の `rec`、`is_first_frame`、`idx`・`k`。記録の先頭(設定)に、実行時に決まる値(上書き後の `G_m_s2`)を記録する。`imu_upda_cov` は範囲内で読まれないので記録しない。

## 5. 段階の再実行(J3・J4)

### 5.1 近傍点の入れ物

`IVox::GetClosestPoint` は、候補が0件のとき出力の入れ物を空にせず `false` を返す(`include/ivox/ivox3d.h` 171〜173 行)。`Nearest_Points` はフレームをまたいで残る(`src/laserMapping.cpp` 519 行は `resize` だけ)。このため、近くに地図がない点は、前に同じ添字に書かれた近傍点で平面を当てはめ(`src/Estimator.cpp` 235〜246 行)、地図への追加の判定(`MapIncremental`)にも使う。

- S7 の入口に、その組の点の `Nearest_Points[idx+j+1]` の呼び出し前の内容(`pid` の列)を記録する。
- この挙動は台帳の起票候補(B で直すか仕様として固定するかは人が決める)。決まるまでは記録で補う。

### 5.2 地図の与え方

- S7 に与える地図は、S3c(初期地図)と、そのフレームの直前までの S8 の記録(挿入の列と退避)を、同じ順に C の iVox に適用して作る。近傍の探索は LRU の順序を動かさない(`ivox3d.h` 138〜210 行)ので、挿入と退避の列から地図を再現できる。
- iVox への挿入の契約(J3 の S3c・S8)が一致していることが前提になる。

### 5.3 トレースの完全性(完了条件2)

B の段階を、B の記録の入口(状態・共分散・隠れた状態・点・近傍点の入れ物・地図)だけで再実行し、出口が記録とビット一致することを確かめる。一致しない場合は、記録から漏れている隠れた状態があるので、第4.5節に足す。共分散を間引いた呼び出しでは、ハッシュ(第4.4節)で確かめる。

## 6. 間引き(J4 だけ)

J1〜J3 の項目と、第4.4節のハッシュは間引かない。J4 の共分散(1回 7.2 KB)だけを、次の規則で間引く。**この規則は C の結果を見る前に確定する**(事前登録 判定 2 節)。

- 状態(42 値)は、すべての S4〜S7 の入口と出口で記録する(J2・J3 と、共分散を記録した呼び出しの J4 に使う)。
- 共分散は、次の呼び出しの入口と出口で記録する。
  - S5・S6 のすべて
  - 各フレームの最初と最後の S7
  - `s7` が 64 の倍数の S7(全体の `call` ではなく S7 だけの通し番号で選ぶ。IMU の到着との相関を避けるため)
  - まれな分岐: LiDAR 更新の分岐(有効点が30以上・未満)、IMU の飽和、更新の失敗のそれぞれで、最初の 100 件
- S7 の J4 は、共分散を記録した呼び出しだけで行う(入口の共分散がないと出口を比べられない)。
- 合成入力では間引かない。
- 注入による確認(事前登録 判定 5 節)は、間引いた後の記録で行う。

見積もり(未計測): ouster-nc-quad-easy は 1985 フレームで、組の数をフレームあたり約 6,500 とすると S7 は約 1,290 万回になる。共分散をすべての S7 の入口と出口で記録すると約 190 GB、上の規則では数 GB の見込み。組の数は BL-007(ダウンサンプルの平均)を B で直した後に数え、この節を確定する。iVox の退避は、容量の既定値(1,000,000 セル)では開発用のデータで起きない見込みで、退避の契約(J3)は合成入力でだけ検出力を持つ。

## 7. ファイル形式(未確定)

PLIN と同じ方針で、1本の順序つきバイナリにする。リトルエンディアン。

- 先頭: マジック(8 バイト)、版、設定(間引きの規則、ソースの版、上書き後の `G_m_s2`)
- レコード: 種別(段階 × IN/OUT)、`call`、`frame`、`grp`、ペイロード長、ペイロード

## 8. 完了条件(計画書 §5)

1. トレースの有効・無効で、両 bag の出力(`odom.bin`、`cloud.bin`)がビット一致する
2. B の各段階を、記録した入口だけで再実行し、出口が記録とビット一致する
3. 意図的に入れた誤り(事前登録 判定 5 節)を、正しい段階で最初の不一致として特定できる
