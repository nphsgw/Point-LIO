# BL-011: Log の L1 基準の根拠の調査

> 以下は `f074322` の BL-011 修正前 B についての記録。後に通常分岐の修正が承認され、[修正後の検証](bl011-b-fix-validation.md)を行った。下端の制約は未修正。

## 結論

`So3Log.InvertsExp` の一律 `1e-12` は、現在の B の計算で回転角 1e-3〜π−1e-3 の範囲全体に保証できる丸め誤差の上限としては根拠が不足している。入力の回転行列を作る丸めが π 近傍で増幅することと、下端で近似分岐に入ることの両方を考慮していない。

ただし、一律 `1e-12` を**達成すべき精度要求**として維持する判断は別にある。その場合、L1 が精度不足を検出したのであり、B の数値計算を改善する必要がある。「B も落ちる」だけでは、テストが誤りだとも、基準を緩めてよいとも決められない。

## 1. 値の出所

- `b2ca192` (2026-10-26) で追加された `tests/math/math_tests.cpp` の `So3Log.InvertsExp` が出所。seed 4、200件、回転角 1e-3〜π−1e-3 に `‖Log(R)−v‖ ≤ 1e-12` を要求する。先頭コメントには丸め・中心差分に基づく旨があるが、確認したコード・コミット説明・計画文書には、この範囲で定数 `1e-12` を導く具体的な式はなかった。
- `10f0931` (2026-10-30、BL-008) で追加された `AccurateAroundNearPiBranch` は、分岐外の上限を `10ε/d²` (`ε=2⁻⁵²`, `d=π−θ`) としている。元の `InvertsExp` の `1e-12` は変更していない。
- 同じく既存の `SmallAngleBranchErrorBound` は、`0.5K` の近似に対して `θ³/6·1.01 + 1e-18` を使う。
- [math-tolerance-proposal.md](math-tolerance-proposal.md) の条件の悪さの説明は、B→C の **L2** をビット一致にする根拠であり、解析解に対する **L1** の一律 `1e-12` を保証する根拠ではない。

## 2. 通常の Log の式の感度

理想の回転を `R* = Exp(v)`、`θ=‖v‖`、単位軸を a とする。B の通常分岐の式を、実数演算で次のように書く。

```text
c = (tr(R)−1)/2
K = (R21−R12, R02−R20, R10−R01)
g(c) = acos(c) / (2 sqrt(1−c²))
w = g(c) K
```

理想の入力では `c*=cosθ`、`K*=2sinθ·a` なので `w=v`。微分すると、

```text
g'(c) = (θ cosθ − sinθ) / (2 sin³θ)
‖K*‖ · |g'(c*)| = |θ cosθ − sinθ| / sin²θ
```

となる。したがって、c の誤差 δc による出力誤差の一次近似は、π 近傍では `π·|δc|/d²` になる。ここで δc には、Log 内の trace の丸めだけでなく、**参照側で回転行列を f64 で作った際の対角成分の誤差**も入る。

一般に、入力を `c*+δc`, `K*+δK` とした場合、一次の項は `g(c*)δK + g'(c*)K*δc`。保証用の上限にするには、二次の項、入力生成、各演算、libm の誤差まで含めた評価が必要である。この一次式だけを、係数まで保証された上限とは扱わない。

小さい角の通常分岐では `g'(c) → −1/6` で、上記の出力感度は `θ/3` に近づく。`acos` 単体の感度だけで、Log 全体の小角での誤差を説明することはできない。下端で問題になるのは、次節の別の近似分岐である。既存の承認済みの許容誤差文書は今回書き換えていない。

## 3. BL-011 の入力を高精度で分解した結果

固定した binary64 を、符号・仮数・指数から高精度値に正確に移した。Boost 1.71 の `cpp_bin_float` を50桁と100桁 (168 bit と334 bit) で使い、同じ Log の実数式を評価した。固定した R に対する結果は両精度で表示した有効桁まで一致した。高精度で作り直す理想 R* の残差は、精度を増やすとさらに小さくなった。

| 計算 | v に対する出力誤差のノルム |
| --- | --- |
| v から高精度で理想の R* を作り、高精度で Log の式を評価 | 100桁で約 `3.08e-97` |
| 実際に渡した f64 の R を正確に読み、高精度で同じ Log の式を評価 | `2.602682890581218e-12` |
| B が実際に計算した trace 由来の c と K に置き換える | この入力では変化なし |
| acos の返値を実際の binary64 に置き換える | `2.623554811322600e-12` |
| sin・除算・出力の積も B の binary64 に置き換える | `2.623182197327663e-12` |

R の生成による最大成分誤差は `3.559684074098908e-16`、`RᵀR−I` の最大成分は `5.214622462742485e-16`。これは有限精度で作った回転行列の通常の規模の誤差である。

この入力では、c の生成時の誤差は `2.578751024569938e-16`、c の評価 (trace 等) の追加の丸めは0。上記の感度は約 `1.018820803900749e4` で、一次近似は `2.627285191912224e-12`。観測された `2.623182197327663e-12` の規模を説明する。

つまり、**このケースでは Log の内部だけを高精度にしても、同じ式を使う限り `1e-12` を満たせない**。また、参照 R を高精度で作って最後に丸めるだけでも、一般には入力の丸めを0にはできない。現在の範囲全体に対する保証を、それだけで得られるとは扱わない。

Boost の算術と sqrt は最近接丸めだが、超越関数の正しい丸めは保証されない。[Boost 1.71 の仕様](https://www.boost.org/doc/libs/1_71_0/libs/multiprecision/doc/html/boost_multiprecision/tut/floats/cpp_bin_float.html)に従い、これは精度を倍にして確認した数値的な原因分析であり、区間演算による厳密な証明ではない。

## 4. 下端 θ=1e-3 の問題

B は `tr(R) > 3−1e-6` なら内部の θ を0とし、結果を `0.5K` にする。実数演算でも、理想の回転行列の trace は、

```text
tr(R*) = 1 + 2cosθ = 3 − θ² + θ⁴/12 − …
```

なので、`θ=1e-3` では `tr(R*) > 3−1e-6`。この分岐に入る。出力は `sinθ·a` となり、誤差は `θ−sinθ ≈ θ³/6`、約 `1.6666666e-10` である。

固定イメージの B に `v=(1e-3,0,0)` と独立 Rodrigues の R を与えると、実測誤差は `1.666666583390042e-10`。この反例は乱数列に依存しない。`InvertsExp` の入力範囲の下端付近と、`SmallAngleBranchErrorBound` の近似の扱いが、一律の上限では整合しない。

## 6. 見直す場合の方針 (未承認)

次の目的を区別して、人が決める必要がある。

1. **範囲全体で一律 `1e-12` の精度を要求する**: 現状 B は達成できない。B の式・近似分岐の改善を先に検討し、承認された修正だけを B に入れる。C だけを改善して B と違う値にすることはしない。
2. **既存の数値アルゴリズムに対する妥当な L1 上限を検証する**: 元の入力範囲と失敗入力を保持し、小角近似の切り捨て誤差、参照 R の生成誤差、通常分岐の条件数、libm と演算の丸めを分けて上限を導く。既存の小角・近 π テストとの整合も取る。固定値を `3e-12` などに替えるだけでは、両端の反例を解決できない。

2を選ぶとしても、B と C の両方の L1 とプランを、根拠・今回見た結果の開示・人の承認を伴う専用の変更で扱う。厳密な全域上限や、そのための libm の誤差仮定までは今回確定していない。**L2 のビット一致・登録済みの (a,r) は別の判定であり、変更しない。**
