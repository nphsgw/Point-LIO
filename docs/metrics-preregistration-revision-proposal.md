# 事前登録の改訂案: 合否の判定の構成

状態: **草案(2026-10-26)。未承認・未レビュー**。この文書は[事前登録](metrics-preregistration.md)を変えない。承認されるまで、現行の規則(τ による B→C の判定)が有効である。採用する場合は、人の承認と別セッションのレビューを経て、事前登録の本文と改訂履歴を専用のコミットで改める。

## 1. 改訂の理由(守りたい性質から)

現行の規則6は、B→C の合否を「B の中央値実行に対する ATE/RPE/Chamfer が τ 以下」で決める。τ は演算順の変種どうしの幅である。この境界には次の2つの欠点がある。

- **検出力がデータに依存する**: avia では、演算順の変種の違いだけで ATE が 0.10 m 動く([fp-order-sensitivity.md](fp-order-sensitivity.md))。τ がこの大きさになると、それより小さい移植の誤り(例: ハーネスの注入で IMU 時刻を 1 ms ずらしたときの ATE 7.9e-6 m)は通ってしまう。
- **感度の低いデータでは、妥当な実装差まで落としうる**: τ は変種5通りの最大値にすぎず、C が使うライブラリ(nalgebra・libm)の演算順の違いを覆う保証はない。

移植で守りたいのは「軌跡が B の変種の幅に入ること」ではなく、次の3つである。

1. 同じ入力に対し、同じ離散的な判断(使った点、更新の成否、飽和の判定、捨てた件数、出力の時刻)をする
2. 1ステップの数値が、演算の特性で説明できる誤差の中で B と一致する
3. 推定器としての品質が B より悪くならない

そこで、判定をこの3つに対応させて分ける。

## 2. 改訂後の判定(案)

| 対象 | 判定 | 基準の決め方 |
| --- | --- | --- |
| イベントの対応・順序・分岐 | 離散的な契約。完全一致 | 不一致は、原因つきの例外としてだけ許す。例外の一覧は報告に載せる |
| 状態の更新・Jacobian・共分散(1ステップ) | B の同じ入力に対する相対誤差 | 演算の特性から決める(条件数、倍精度の ulp の何倍まで、など)。B の変種間の1ステップの差でも裏を取る。数値は部品のゴールデン出力を作る時点で、C の結果を見る前に登録する |
| 軌跡・地図(累積) | 正解に対する品質の非劣化と、上の2つ | 正解に対する ATE が Δ_gt(現行の規則5)以下。τ は感度分析として報告するが、合否に使わない |

- 現行の規則1〜5(中央値実行、変種 V0〜V4、τ と Δ_gt の求め方)は、感度分析と Δ_gt のために残す。
- 現行の規則7(τ を広げて通さない)は、上の各基準に読み替えて残す。
- 現行の規則8(τ_B が τ を超えたら止める)は、B の修正が演算順への感度を変えたことの報告として残す。B→C の判定を止める条件にするかは要確認。

### 未確定の点(要確認)

- avia-quick-shack には正解がない。累積の判定は ouster-nc-quad-easy だけになり、avia は上の2つ(離散・1ステップ)と、感度分析の報告だけになる。これでよいか。
- Δ_gt を非劣化の境界にそのまま使うか、余裕を設けるか。余裕を設けるなら、C の結果を見る前に数値を決める。
- 1ステップの相対誤差の具体的な数値(ulp の倍数、条件数との関係)。部品ごとに決める。
- 最終評価用のデータ([計画書](rust-reimplementation-verification-plan.md) §3)の L3 の基準。正解つきなら Δ_gt と同じ求め方にするか。

## 4. 注入による確認(採用の条件)

改訂後の各判定は、使う前に、意図的に入れた誤りで落ちることを確かめる。落ちない判定は採用しない。

| 注入 | 落ちるべき判定 |
| --- | --- |
| 状態または共分散に NaN を1つ | 1ステップ、累積(発散) |
| IMU またはLiDAR の時刻 +1 ms | 離散(出力の時刻)、1ステップ |
| 入力レコードの1件欠落 | 離散(件数) |
| レコード種別の入れ替え | 離散(順序) |
| 1フレームの点の一部欠落 | 離散(使った点)、1ステップ |
| 段階を指定した誤り(予測・IMU 更新・LiDAR 更新・地図更新のいずれかに小さな摂動) | 1ステップ。トレースで、指定した段階が最初の不一致になる |
