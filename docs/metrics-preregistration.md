# 指標と許容誤差の事前登録

状態: **承認済み(2026-10-21)。許容誤差の規則を改訂(2026-10-26、下の「改訂履歴」)**。以降は変更しない。変更が必要になったら停止して報告し、人の承認を得て、理由つきの専用コミットで改訂する。

この文書は、いずれのバイナリの実行結果も見る前に書く。数値の許容誤差そのものは、A の10回実行(計画書フェーズ0の4)のばらつきから機械的に導く規則だけをここで決める。

[evaluation-data.md](evaluation-data.md) の2本。SHA256 が一致しないデータでは実行しない。

| ID | 精度の基準 |

| ouster-nc-quad-easy | 正解軌跡(gt-nc-quad-easy.csv)に対する ATE/RPE |
| avia-quick-shack | 正解なし。精度は A の軌跡に対する相対値のみで見る |

## 実行条件(比較する実行すべてで固定して記録する)

- 同一マシン、同一 Docker イメージ(イメージ ID を記録)
- スレッド数(`MP_PROC_NUM`)を固定して記録する。A は既定値と1スレッドの両方を測る
- 最適化フラグ(`-O3`、`-march=native`、`-ffast-math` の有無)をビルドログで確認して記録する
- 入力は bag を最初から最後まで、同じ順序で与える。再生速度の影響を避けるため、実時間再生ではなく入力ファイル経由(フェーズ0の実行ハーネス)で比較する。ハーネスができるまで、性能の数値は登録対象にしない
- 各構成(A、B、C)につき10回実行する

## 精度の指標

ツールは `evo`(バージョンを記録)。

1. **ATE**: 並進 RMSE [m]。SE(3) アラインメント(スケールなし)。
2. **RPE**: 並進誤差 RMSE [m] と回転誤差 RMSE [deg]。区間は 1 s と 10 m の2通り。
3. **Chamfer 距離** [m]: 最終地図(各フレームのダウンサンプル済みワールド点を、初期地図構築後の全フレームについて累積した点群)をボクセル 0.1 m で間引いた点群同士の対称 Chamfer 距離(各点から最近傍までの距離の平均を、双方向で平均する)。

ouster-nc-quad-easy は正解に対する ATE/RPE を出す。avia-quick-shack は、正解がないため次の相対値だけを出す。

- 構成 X の軌跡の、A の中央値実行(後述)に対する ATE/RPE

## 安定性の指標

- **発散**: 次のいずれかを満たす実行を1回と数える。(a) 異常終了、(b) 状態や共分散に NaN/Inf、(c) 隣接フレーム間の並進が 10 m を超える。
- **実行間ばらつき**: 同一構成の10回実行の、上の各指標の最小・最大・標準偏差。

## 性能の指標

- フレームあたり処理時間(1フレームの前処理から状態更新まで)の p50 / p95 / p99。最初の10フレームは除く。
- ピークメモリ(最大常駐セット、RSS)。
- 平均 CPU 使用率。

性能は合否にしない。A→B と B→C の比と分布を報告するだけとする。

## 許容誤差の規則

A の実行から、次の手順で機械的に決める。

1. 精度の各指標について、A(既定のビルド)の10回の値の最小・最大を出す。
2. **中央値実行**: 10回のうち、他の9回との ATE の中央値が最小の1回。
3. **演算順の変種**: A を、ソースを変えずに、IEEE の意味を保ったまま演算順・丸めだけが変わる次の5通りでビルドする(`-ffast-math` は使わない)。コンパイラはイメージの gcc 9.4 のみ。
   - V0: 既定(`-O3`。上の1・2の10回と同じビルド)
   - V1: `-march=native`(FMA と AVX)
   - V2: `-mfma`(FMA と AVX。gcc の `-mfma` は AVX を含む。AVX2 以降なし)
   - V3: `-mavx2 -ffp-contract=off`(ベクトル化のみ。FMA なし)
   - V4: `-march=native -ffp-contract=off`(AVX のみ。積和の結合なし)
   `-march=native` は実行機の CPU に依存する(現機は AMD Ryzen 7 7700X)。CPU を記録し、比べる実行はすべて同じ機械で行う。V1〜V4 は各2回実行し、同じ変種の2回が一致するかを記録する。一致しない変種は、全実行を次の組に含める。
4. **基準幅 τ** = 変種どうしの全組(各変種の代表実行、V0 は中央値実行。5変種なら10組)の ATE の最大値。RPE と Chamfer も同様に、組ごとの値の最大値。同じ変種の中の揺れ(V0 の10回どうしなど)が変種どうしより大きい指標は、その最大値を使う。
5. **正解に対する精度の上限**(ouster-nc-quad-easy のみ): Δ_gt = **B** の変種(3 と同じ5通り)の代表実行の、正解に対する ATE の最大値。C を B と比べるため、A ではなく B から求める。
6. 判定:
   - A→B: 差を報告する。合否にしない。
   - B→C: C の各実行(10回)について、次をすべて満たせば通過。1回でも満たさなければ不通過。
     - B の中央値実行に対する ATE/RPE/Chamfer が、すべて τ 以下(両 bag)。
     - 正解に対する ATE が Δ_gt 以下(ouster-nc-quad-easy)。
7. τ に下限や倍率は設けない。C が τ を超えた場合、τ を広げて通さず、停止して報告する。
8. B についても 3・4 を行い、B の幅 τ_B を出す。いずれかの指標で τ_B が A の τ を超える場合(修正で演算順への感度が変わった)は、B→C の判定をせず、停止して報告する。

## 改訂履歴

- 2026-10-26: 許容誤差の規則 3〜8 を改訂(人の承認による)。旧規則は「τ = A の10回どうしの最大値。τ が0に近くても下限なし」だった。A は同じビルドでは決定的で(ROS 経路で44回ビット一致)、旧規則の τ は ATE で 1e-16〜1e-15 m になる。一方、ビルドフラグだけを変えた A で ATE が 8 mm〜0.10 m 変わり([fp-order-sensitivity.md](fp-order-sensitivity.md))、旧規則では正しい移植でも B→C が不通過になる。旧規則の意図(同じ実装の自然な揺れの幅)に合わせ、演算順の変種の幅を τ とした。**この改訂は、V0・V1 の差の大きさ(上の文書)を見た後に行った。** V2〜V4 の結果と、C の結果は見ていない。

ステップ単位(IKFoM の1ステップ、iVox 近傍探索など)の許容誤差は、フェーズ2の単体ゴールデン出力を作る時点で別途登録する。

## 事前に決めていない点(承認時に確認)

- RPE の区間(1 s と 10 m)、Chamfer のボクセル(0.1 m)、発散判定の 10 m、除外する最初の10フレーム。いずれも私の仮定
- τ の定義に最大値を使うこと。標準偏差の倍数にするより厳しいが、10回では分布の裾が見えない。
- avia-quick-shack には正解がなく、精度の「正しさ」は評価できない。A との一致しか見ていないことを報告に明記する。
